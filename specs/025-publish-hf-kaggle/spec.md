# Feature Specification: publish the PerioBench datasets and a quickstart on Hugging Face and Kaggle

**Branch**: `spec/217-025-publish-hf-kaggle`

**Created**: 2026-10-28

**Status**: draft

**Input**: "We should publish the applicable datasets and notebooks to both Hugging Face and Kaggle. Hugging Face
is https://huggingface.co/healthtransformationlab. Update it to be as user friendly as possible."

> Personal learning project; synthetic data; public sources only (`DISCLAIMER.md`). Spec 020 decided what may be
> published and built it for Kaggle; this spec adds Hugging Face, a quickstart notebook for both, and one
> workflow. The same rules hold: everything published is generated by this repo, nothing from `data/external/`
> or `data/raw/`, no `simulated_*` file, no `sim:`/`calib:` row, no MedGemma weights, CC BY 4.0.

## Where things stand

- Kaggle: `kaggle/publish.py` and *Publish datasets to Kaggle* exist (spec 020) but have never been run (spec 020
  T005), so neither dataset is on Kaggle yet.
- Hugging Face: the `healthtransformationlab` organisation exists and is empty: no datasets, no card.

## User stories

### US1 - The PerioBench datasets are on Hugging Face and load in one line (P1) #217

A newcomer opens `healthtransformationlab/perio-bench-notes`, sees the notes in the dataset viewer as a `train`
and a `test` split, and loads them with `load_dataset("healthtransformationlab/perio-bench-notes")` or one
`pandas.read_csv("hf://datasets/...")` line. The results dataset opens on the leaderboard.

**Acceptance**:
1. **Given** the build, **then** the files are exactly spec 020's list for that dataset, passed through the same
   check (no simulated, external, partial or `sim:`/`calib:` file), plus split files derived from them.
2. **Given** the notes, **then** `data/train.csv` and `data/test.csv` share one column set (the note, its label,
   grade, extent, what the clinician wrote, the X-ray reading), so the viewer and `load_dataset` show both splits;
   the full original files stay under `raw/` for anyone who wants every column.
3. **Given** the card, **then** its YAML header declares the licence, language, task, size, tags and the
   `configs` (splits and extra tables), and its body starts with a quick start and says synthetic, not
   affiliated, not for clinical use, how it was made, licence and how to cite.

### US2 - A quickstart notebook that runs on Kaggle and in Colab (P1) #218

`notebooks/perio_bench_quickstart.ipynb` finds the notes wherever it runs (attached Kaggle dataset, Hugging Face
from Colab, or a local checkout), shows them, trains a TF-IDF and logistic-regression baseline on a CPU in about
a minute, scores it on the 240 review notes with a 95% interval, and puts it beside the published leaderboard.

**Acceptance**: a test runs the notebook's code against the local data and gets an accuracy within the
leaderboard's range for that kind of method; every printed number says synthetic; the notebook is published as a
public Kaggle notebook attached to `perio-bench-notes`, and the Hugging Face and Kaggle cards link it with an
"Open in Colab" badge.

### US3 - One Actions workflow publishes to Kaggle, Hugging Face or both (P1) #219

*Publish datasets* (`kaggle-publish.yml`) gains a `platform` choice: `both` (default), `kaggle`, `huggingface`.
It publishes the datasets and the quickstart notebook; each Kaggle version and Hugging Face commit names the
repository commit.

**Acceptance**: with Hugging Face chosen and no token, the run fails before any work, naming
`HF_PUBLISH_TOKEN`; with a token, it checks the shape (`hf_`), then one authenticated call (`whoami`) and that
the token can write to the organisation, before uploading. The token is in `ops/secrets_register.yaml`.

### US4 - The Hugging Face organisation page says what the lab is and where to start (P2) #220

The organisation card (the `healthtransformationlab/README` Space, which Hugging Face shows on the organisation
page) gives the goal, the three benchmarks (PerioBench built; OralHealthBench and AccessBench proposed), the
datasets and the quickstart, links to healthtransformationlab.org, GitHub and Kaggle, and the personal-project and
synthetic-data labels. It is published by the same workflow from `huggingface/cards/org.md`.

## Requirements

- **FR-001** Hugging Face files come from spec 020's lists (`kaggle/publish.py`), never a second list, so the two
  platforms can't drift.
- **FR-002** Cards are markdown in the repo, reviewed like code; the platform pages are never edited by hand (the
  next version would overwrite it). Each card links the other platform.
- **FR-003** Publishing runs only from GitHub Actions, environment `dev`.
- **FR-004** A refused upload fails the run (Kaggle: status checked, as spec 020; Hugging Face: the API raises).
- **FR-005** The Hugging Face token is fine-grained: write access to the `healthtransformationlab` organisation's
  repositories only, 90 days at most.

## Out of scope

- The fine-tuned note classifier (spec 020 US3, #122) on Hugging Face: once it exists on Kaggle, a follow-up.
- OralHealthBench and AccessBench data: none exists yet.
- The organisation avatar and the Kaggle collection: owner steps on each site, listed in the README.

## Success criteria

- SC-001 Both datasets are public on both platforms, CC BY 4.0, matching the repository at the published commit.
- SC-002 A newcomer can go from the organisation page to a scored baseline in under five minutes, with no setup.
- SC-003 Nothing simulated, external or real is on either platform.
