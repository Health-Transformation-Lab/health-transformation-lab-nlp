# dental-omop-nlp

Can a small language model read a dental SOAP note and return the patient's
periodontal status? This repo is the benchmark that answers it: synthetic
dental records → OMOP CDM extended for tooth-level data → a ladder of models
from rules to BERT-family encoders to a large LLM, all scored on the same
patient-level test split.

**Ground rules**

- **Synthetic data only.** Every patient here was generated by
  [Synthea](https://github.com/synthetichealth/synthea). No PHI, no real
  records, no employer or partner data, ever. Pull requests that add real data are
  closed on sight.
- **Public until approved for internal use.** This is a personal research
  prototype. If it is adopted inside an organization it moves to that
  organization's workspace; this repo stays the public reference.
- **Two languages, one contract.** The data science side works in R, the
  data engineering side in Python. Both read and write the same OMOP tables
  and the same test split, and both report through the same scorer, so a
  number from either side is comparable.
- **Small samples.** Sized to run on a laptop or Databricks Free Edition
  (CPU-only serverless, Python/SQL). A few hundred to a few thousand notes,
  not a million.

## What's in here

| Path | What it is |
|------|------------|
| `models.yaml` | The model registry: 12 candidate encoders with role, context length and HF id, plus the benchmark ladders. Start here. |
| `synthea/` | Synthea run script, config, and the custom dental modules (perio exam, caries, restorations). |
| `omop/` | OMOP CDM 5.4 DDL subset plus the dental extension (`SITE`, `SITE_EVENT`) adopted from the OHDSI Dentistry Workgroup. |
| `python/` | Python pipeline: Synthea CSV (or stand-in) → OMOP → labels → synthetic SOAP notes → rungs → score. |
| `r/` | R pipeline: the same steps via OHDSI `ETL-Synthea`, `tidymodels` and `text`. Local run steps and GPU guidance in `r/README.md`. |
| `eval/` | The shared scorer and the split definition. Both languages call this. |
| `databricks/` | Notebooks that run the Python path on Databricks Free Edition. |
| `docs/` | ADRs, the plan, and the working notes. |
| `data/samples/` | A handful of generated rows checked in so the repo runs end to end without Synthea. |

## The pipeline

```
Synthea (dental modules)
   │  CSV / FHIR
   ▼
OMOP CDM 5.4 + dental extension          ← omop/ddl/
   │  PERSON, CONDITION_OCCURRENCE, PROCEDURE_OCCURRENCE,
   │  MEASUREMENT (probing depth, BOP, bone loss), SITE, SITE_EVENT
   ▼
Perio chart → label                      ← python/dental_omop_nlp/labels.py
   │  healthy / gingivitis / periodontitis stage I–IV (AAP/EFP 2017, simplified)
   ▼
Chart → synthetic SOAP note              ← python/dental_omop_nlp/notes.py
   │  NOTE table; the chart is the ground truth for the note
   ▼
Patient-level split                      ← eval/split.py
   ▼
Model ladder                             ← models.yaml
   │  rules → structured baseline → DistilBERT → … → BioClinical-ModernBERT → LLM
   ▼
Scorer                                   ← eval/score.py
   │  macro F1, per-class F1, sensitivity, specificity, AUROC
   ▼
NOTE_NLP                                 ← the flag lands in OMOP, never a diagnosis
```

## Quick start

```bash
# 1. Optional: real Synthea patients (needs Java 11+). Skip it and step 2
#    builds a stand-in population so everything runs without Java.
./synthea/run_synthea.sh 500

# 2. Python side
cd python
pip install -e .
python scripts/01_build_dataset.py         # OMOP parquet + labeled SOAP notes (no Synthea needed)
python scripts/02_split.py                 # patient-level train/test split, made once
python scripts/03_run_ladder.py --rungs rules_baseline,structured_baseline,tfidf_logreg

# 3. R side (see r/README.md)
cd .. && Rscript r/run_ladder.R rules_baseline structured_baseline tfidf_logreg
```

Each script is a thin wrapper over a function in `dental_omop_nlp/`, so the
same code runs from a notebook in `databricks/`.

## Status

v0.1: runs end to end on stand-in data; R and Python agree to 1e-16. First
finding: the synthetic notes are too easy (rules baseline 0.97 macro F1), so
making the notes realistic comes before running the BERT ladder. See
[docs/plan.md](docs/plan.md) for results, next steps and open decisions.

On Databricks Free Edition: add this repo as a Git folder and run
`databricks/notebooks/01_run_benchmark.py`.
